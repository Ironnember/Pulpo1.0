# Gladiator Ultimate Tournament — proposed Pulpo integration

Status: experimental, intelligence-plane testing protocol; **not** an authority source.

For material Pulpo assessments, run the existing Operate Pulpo workflow and
Gladiator together. Gladiator constructs mixed teams of adverse conditions
(including light+dark, starve+empower, mirror+invert, replay+revoke,
substitute+aggregate), pits teams against one another, retains reproducible
counterexamples, and tests evolved attacker/defender candidates on held-out cases.

An ultimate opponent or hero is **relative to the bounded tested environment**,
never universally proven. A tie or unknown outcome is valid. Do not grant
new credentials, budget, provider routes, or authorization for testing.

The `pulpo.gladiator_gate` module is deliberately narrow: it checks whether
a proposed assessment-completion record includes both Pulpo and Gladiator
evidence, an exact object/revision, teams, battles, independent verdict,
reconciliation, and held-out coverage. It is a **presence gate only**. Strings
such as `evidence:...` are untrusted references; the module does not verify
provenance, authenticity, independence, or battle correctness. A passing gate
must never authorize execution or certify a consequence.

path after inspecting its actual schema and trust boundary; add authenticated
artifact resolution and adversarial evidence substitution tests. Do not create
